# Confluence UI 분석 (읽기 전용 화면)

`rea capture-browser-scenario`로 사용자 Chrome(CDP)에 연결해 수집했다. 원본 캡처, 스크린샷, 접근성 트리는 `analysis/raw/scenarios/`에 있고 git에서는 제외한다.
이 문서는 새 서비스의 **기능 명세 참고 자료**다. Atlassian의 코드나 자산은 가져오지 않는다.

## 화면별 구성

### 공통 상단 바
- 사이드바 토글 (`Ctrl+[`), 앱 전환, 로고(→ `/wiki`)
- 통합 검색창: Confluence, Jira, SharePoint 등 연결 앱을 함께 검색. Enter 키를 누르면 고급 검색으로 이동
- **만들기** 버튼과 템플릿 선택 드롭다운
- 알림(배지), 도움말, 관리(설정), 프로필
- Rovo(AI) 질문 버튼 → 사내 서비스에서는 범위 밖. 추후 사내 LLM 연동을 검토한다.

### 페이지 보기 (`/wiki/spaces/{key}/pages/{id}/{slug}`)
- 헤더: 마지막 업데이트(→ 버전 기록), **현재 보는 사용자 아바타(실시간 presence)**, 편집, 공유(권한 상태 표시), 링크 복사, 추가 작업(…)
- 본문 메타: 작성자, 날짜, 듣기(TTS), 반응(이모지)
- 본문 하단: 레이블 추가, 반응, 댓글 추가
- 우측 플로팅 바: 댓글 보기, 세부 정보 패널, Loom 녹화, 리믹스
- URL은 숫자 ID가 기준이고 slug는 장식이다. 리다이렉트 시 slug가 붙는다.
  → **마이그레이션 후에도 기존 URL `/wiki/spaces/{key}/pages/{id}`를 새 페이지로 리다이렉트할 수 있도록 원본 ID를 보존해야 한다.**

### 사이드바 (스페이스 내비게이션)
- 스페이스 이름과 아이콘, 스페이스 메뉴(…)
- **바로 가기**: 스페이스 관리자가 고정한 링크 목록
- **콘텐츠 트리**: 계층형 페이지 트리. 펼침과 접힘, 현재 페이지 강조, `+`(하위 페이지 생성), 정렬 및 필터, **제목 검색** 지원
- 하단에 `+ 만들기`

### 버전 기록 (`/wiki/spaces/{key}/history/{id}`)
- 좌측: 선택한 버전의 본문. 우측: 월별로 묶은 버전 목록(V번호, 일시, 작성자, `현재`/`레거시` 배지)
- 버전별 메뉴(…): 복원, 비교
- **변경 사항 강조 표시** 토글 (diff)
- `레거시` 배지: 구 편집기로 작성한 버전. 서식 차이가 있을 수 있다는 안내가 나온다.
  → **마이그레이션 시 레거시 XHTML과 신 편집기 콘텐츠를 모두 변환할 수 있어야 한다.**

### 검색 (`/wiki/search?text=`)
- 상단 탭: 전체 / Confluence / Jira / 연결된 외부 앱
- 필터: 마지막 업데이트(기간), 유형(페이지, 블로그, 첨부 등), 스페이스, 정렬(관련성, 최신)
- 결과 항목: 제목, 유형, 스페이스, 상대 시간, 댓글 수, 최근 편집자, **키워드가 강조된 본문 발췌**, 관련 링크
- 한국어 형태소 검색 품질이 중요하다. 예를 들어 "획득"으로 "획득을", "획득 시" 같은 표현도 찾아야 한다.

### 스페이스 개요 (`/wiki/spaces/{key}/overview`)
- 스페이스 홈 페이지 본문(아이콘, 제목, 패널 매크로 등)
- 최근 스페이스 활동(사용자별로 묶음, 필터 가능), 스페이스 기여자

### 편집기 (`/wiki/spaces/{key}/pages/edit-v2/{id}`)
사용자 개인 스페이스의 테스트 페이지(`test`, 1998782495)에서만 분석했다. 게시하지 않았고 초안만 남아 있다.
- 헤더: 이동 경로, 제목, **저장 상태("저장됨" → 버전 기록 링크)**, 편집 중인 사용자 아바타, **업데이트(게시)**와 게시 옵션, 닫기, 공유, 링크 복사
- 툴바: 텍스트 스타일(일반, 제목), 굵게와 서식 더 보기, 글머리 및 번호 목록, 정렬, 텍스트 색상 | 작업 항목(체크박스), 이미지·동영상·파일, 멘션, 이모지, 레이아웃(다단), 탭, 동기화 블록, 표(크기 선택), 요소 삽입(+) | 링크 | 실행 취소, 다시 실행, 변경 사항 보기 | 툴바 고정
- 제목 영역: 정렬, 이모지 아이콘, 상태, 헤더 이미지, 너비 조정(고정 폭 / 전체 폭)
- **`/` 슬래시 명령**: 자동 완성 목록에서 링크(`Ctrl+K`), 다이어그램, 데이터베이스, 작업 항목(`[]`), 이미지·파일, 멘션(`@`), 동기화 블록, 이모지, Jira 업무 항목, 펼치기(expand) 등을 고른다. 마크다운식 단축 입력도 지원한다.
- **저장 모델**: 게시와 초안이 분리되어 있다.
  - 편집 내용은 실시간 협업 채널(socket.io `/ncs/.../confluence/socket.io`)로 계속 전송된다.
  - 초안은 서버에 자동 저장된다(`PUT /wiki/rest/api/content/{id}`).
  - 사용자가 **업데이트**를 눌러야 새 버전이 게시된다.
  - 편집 세션 시작 시 heartbeat(`/wiki/api/v2/editor/heartbeat/start`)를 보낸다.
- 신 편집기 storage 형식은 문단마다 `local-id` 속성을 붙인다. 예: `<p local-id="69183433e7d4">`. 인라인 댓글 위치와 동기화 블록 참조에 쓰이는 것으로 보인다. → 변환기에서 블록 ID로 보존을 검토한다.

### 라이브 문서, 화이트보드, 데이터베이스
사용자 개인 스페이스의 테스트 문서 3개를 읽기 전용으로 열어 분석했다(`test_live`, `test_whiteboard`, `test_database`).

| 유형 | 사내 사용량 (CQL) | 저장 방식 | REST API로 본문 조회 |
|---|---|---|---|
| 라이브 문서 (`page`, subtype `live`) | 1,152 | 일반 페이지와 같은 협업 채널(`/ncs/.../socket.io`). 게시 단계 없이 입력 즉시 반영. 버전은 `ncsStepVersion`으로 관리 | **가능** (storage, ADF) |
| 화이트보드 (`whiteboard`) | 33 (18개 스페이스) | 별도 캔버스 서비스(`canvas-workers.atlassian.com`)의 WebSocket 문서. `referenceId`(UUID)로 식별 | **불가** (본문이 빈 값으로 옴) |
| 데이터베이스 (`database`) | 48 (18개 스페이스) | 화이트보드와 같은 캔버스 서비스. 초기 로드는 `.../document/{uuid}/steps/...`, 이후 WebSocket | **불가** (본문이 빈 값으로 옴) |
| 폴더 (`folder`) | 600 | 페이지 트리의 컨테이너. 폴더 아래 페이지 2,253개 | 메타데이터 가능 |

- **화이트보드**: 수집 환경(서비스 워커 차단, 1440×900 고정)에서 "문제가 발생했습니다" 오류 화면이 떠서 UI 구성은 관찰하지 못했다.
- **데이터베이스 UI**:
  - 보기(view) 탭 여러 개, 필터, 정렬, 필드 숨기기, 설정, 검색
  - 타입이 있는 필드(텍스트, 태그, 사용자 등. `+`로 추가)
  - 행 번호와 행 선택, 항목 추가, 열별 **계산**(합계 등)
  - 템플릿(요구사항 추적표, 회의 액션 목록, 성과 지표 대시보드)
- **라이브 문서 UI**: 일반 편집기와 같다. 다만 "업데이트(게시)" 버튼이 없고 "N분 전 편집됨"으로 표시된다.
- **인벤토리 보완 필요**: 화이트보드, 데이터베이스, 폴더는 `confluence-inventory.mjs` 집계에 빠져 있다. 폴더 아래 페이지는 깊이가 0으로 계산되었다.

## 관찰된 실시간 및 백엔드 기능
- **Presence**: socket.io(`/ncs-presence/.../socket.io`)로 페이지별 현재 접속자 표시
- GraphQL 구독(WebSocket): 알림 등 실시간 갱신
- 미디어 API(`/media-api/file/{uuid}/image`): 첨부 이미지를 UUID로 저장하고 썸네일 제공
- 이모지(표준, 사이트 커스텀), 단축키, 권한 확인(`permissions/permitted`), 생성 대화상자용 스페이스 목록
- 페이지 한 번 열 때 fetch/xhr 요청 약 130건이 발생한다(분석과 실험 플래그 포함). 새 서비스는 페이지 로드 API를 1~3회 수준으로 단순화하는 것을 목표로 한다.

## 새 서비스 MVP 기능 도출
| 영역 | MVP | 후순위 |
|---|---|---|
| 내비게이션 | 상단 바, 스페이스 사이드바, 페이지 트리(드래그 이동, 제목 검색) | 바로 가기, 스페이스 아이콘 |
| 페이지 | 보기, 편집, 하위 페이지 생성, 링크 복사, 레이블, 기존 URL 리다이렉트 | 반응, 듣기(TTS) |
| 편집기 | 블록 에디터(제목, 목록, 표, 코드, 이미지·파일, 링크, 멘션, 작업 항목, 펼치기, 패널, 레이아웃), `/` 명령, 초안 자동 저장과 게시 분리 | 동시 편집(Yjs), 동기화 블록, 탭, 다이어그램, 데이터베이스 |
| 버전 | 버전 목록, 보기, 비교(diff), 복원 | 월별 그룹 UI |
| 검색 | 전문 검색(한국어), 스페이스, 기간, 유형 필터, 발췌와 키워드 강조 | 외부 앱 통합 검색 |
| 협업 | 댓글(일반, 인라인), 알림 | presence, 동시 편집 |
| 스페이스 | 개요, 최근 활동, 권한 | 템플릿 |
| 인증 | Entra ID SSO | |
| 콘텐츠 유형 | 폴더, 라이브 문서(동시 편집 기반, 게시 단계 없음) | 데이터베이스(필드 타입, 뷰, 필터, 계산), 화이트보드(Excalidraw 임베드) |
| 설정·관리 | 사이트 설정, 스페이스 설정, 멤버 권한, 휴지통 — 상세는 `settings-analysis.md` | 분석, 감사 로그 UI, 공지 배너, 모양새 |
